# Quotation Builder to n8n Handoff

Status: Builder-side contract for Phase A commercial-model completion.
Source: `index.html` payload construction and `pricing-config.js`; Odoo test IDs come from `odoo-templates_quotation-builder-comprehensive_27082026.xlsx`.

## Routing authority

`odoo_routing` is authoritative for the Odoo entity. It is resolved from the selected salesperson, not from the customer's country:

```json
{
  "source": "salesperson",
  "salesperson_name": "David Sturdy",
  "user_id": 4,
  "entity_key": "UK",
  "sales_team_id": null,
  "sales_team_label": "UK"
}
```

`customer_country_id` remains customer metadata. n8n should use `odoo_routing.entity_key`, `user_id` and `sales_team_id` for Odoo routing and use the country field only as customer data.

## Commercial models

The payload always contains the primary quote fields plus `full_opex_quote`:

- `commercial_model: "capex_opex"`: primary CAPEX/investment quotation plus the normal recurring subscription quotation.
- `commercial_model: "full_opex"`: the CAPEX-for-OPEX installation/investment quotation remains required, while the recurring package quotation uses the five-year Full OPEX template and price list.
- `commercial_model: "both"`: the primary CAPEX + OPEX route is retained and `full_opex_quote.requested` is `true`. The current Builder does not emit two complete top-level quote objects; n8n must create the two documents from the primary quote and the nested Full OPEX scenario.

`full_opex_quote` contains:

```text
requested, enabled_for_generation, mapping_complete, term_years
segment, package, sensor_type, vendor, sensor_count, tier
monthly_hardware_rate_per_sensor, monthly_hardware_total
monthly_subscription_total, monthly_total, installation_capex_total
capex_for_opex_template, capex_pricelist, pricelist, package_template
missing_mapping, note
```

Full OPEX is only selectable when `enabled_for_generation` is true. `term_years` is five for the Full OPEX route. Installation remains a one-off CAPEX amount; hardware and subscription are monthly values.

## Odoo fields n8n should consume

Primary quote aliases are kept for compatibility:

```text
template_id                 primary CAPEX/base template ID
pricelist_id                primary CAPEX price list ID
capex_pricelist_id          primary CAPEX price list ID
subscription_template_id    recurring package template ID
subscription_pricelist_id   recurring package price list ID
opex_pricelist_id           recurring package price list ID
instore_addon_template_id   in-store recurring add-on template ID
instore_addon_pricelist_id  in-store recurring add-on price list ID
```

The structured equivalents are under `odoo_template`, `odoo_price_lists` and `subscription_quote`. Prefer the structured objects when available; keep the aliases for the existing n8n contract.

For Full OPEX, use these nested fields to create the recurring quotation and the mandatory installation quotation:

```text
full_opex_quote.capex_for_opex_template.template_id
full_opex_quote.capex_pricelist.pricelist_id
full_opex_quote.package_template.template_id
full_opex_quote.pricelist.pricelist_id
full_opex_quote.term_years
full_opex_quote.installation_capex_total
```

Do not derive template or price-list IDs from customer country, package labels, display totals or UI text.

## Quantity and technology rules

`odoo_line_quantity_rules` is the Builder's explicit product-line instruction list. Each item has `product_id`, `action`, `quantity`, role and source. Supported actions are:

- `set_quantity`: set the selected Odoo product line quantity.
- `remove`: set the non-selected mapped product line to zero/remove it.

The rules currently cover:

- Isarsoft servers, resolved per physical location and aggregated by server profile.
- Retail Chain LiDAR processing units.
- Retail Chain Xovis processing units: zero for 1–9 sensors, exactly one for 10–350, and fail closed with review required above 350.

Isarsoft remains explicit in `isarsoft.mode`: `none`, `base` or `addon`. `existing_network_reused` means camera hardware is excluded, but server and setup remain in scope. `isarsoft.server` and `isarsoft.location_resolution` contain the sizing evidence.

## Validation gate

n8n must stop automated generation when `commercial_mapping_complete` is false or `mapping_validation.valid` is false. Review `mapping_validation.errors` before creating an Odoo quotation. This is especially relevant for DE, where the workbook currently contains unresolved IDs and no DE Isarsoft IDs.

`financials`, `results` and displayed totals are indicative Builder calculations. Odoo remains authoritative for final price, taxes, templates and quotation totals.

## Fixture coverage

`outputs/QB-PAYLOAD-FIXTURES.md` contains eleven payloads generated by executing the current Builder `payload()` function, including NL/UK Isarsoft, Retail Property Re-ID, LiDAR/Xovis processing-unit rules, Full OPEX, Both quotations and an intentionally incomplete DE mapping.

`outputs/QB-MAPPING-DIFF.md` records the workbook-to-Builder mapping and unresolved items. n8n changes are intentionally out of scope for this Builder phase.
